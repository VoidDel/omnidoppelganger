# OmniDoppelganger

OmniDoppelganger（`odg`）是一个跑在你自己电脑上的编码 agent 桌面应用：Rust 核心，Tauri 外壳，React 界面。

你选一个文件夹，交代一件事；分身读文件、搜索、改文件、跑命令。读和改这个文件夹里的文件不用问你，每条命令、每次碰文件夹外面的路径、每次改 `.git` 里的文件，都先等你点头。

## 现在能做什么

当前是 v0.1，第一条主线已经打通：

- 在一个文件夹里开会话，流式对话，会话保存在本机，重开后原样恢复；会话可以改名、删除，侧栏能按标题、文件夹和说过的话搜索
- 工具：读文件、搜内容、按名找文件和列目录、改文件（带改动对比，可一次改多处，要么全改要么不改）、整文件写入、跑命令。不会自己结束的命令（开发服务器、监视器）可以放到后台跑，分身随时看它的输出、把它停掉；后台命令在应用关闭时一并结束
- 多家模型供应商：Anthropic、OpenAI、DeepSeek、Kimi（月之暗面）、GLM（智谱），以及任意 OpenAI 兼容服务。每个会话固定用化出时选的那一家，但可以随时在这一家之内换模型：点输入框下方的"功法"，列表是直接向供应商问来的（问不到时用内置的几个）；设置页里的模型列表也一样
- 四种禁制（权限模式），输入框下方切换，或在输入框里按 Shift+Tab：
  - **步步请示**：改文件也要先批准
  - **自行改文件**：文件夹内的改动自行执行，命令要批准（默认）
  - **先谋后动**：不改文件，分身摸清情况后呈上计划，一键换禁制照计划动手
  - **放手施为**：只读、构建、测试类命令自行执行，其余命令仍要批准。是否放行由规则判断（`safety.rs`）：整条命令按 shell 的方式拆开，每一段都得是已知的读取、构建、测试命令，不能写文件、不能用文件夹之外的路径、不能藏着执行别的代码，拿不准就请示。它防的是失手，挡不住存心绕过它的模型
- 审批：命令和文件夹之外的路径要先批准，可以只准一次，也可以之后都准；命令还可以选"这处洞府里永远都准"，重启之后也算数，在设置里能逐条撤销。命令的"之后都准"只覆盖同一个前缀（如 `cargo test`），带管道、分号、引号、变量的命令和 `sh`、`python` 这类解释器每次都要批准；改 `.git` 里的文件每次都要批准，因为 Git 的钩子和配置会在你自己运行 git 时生效
- 长会话自动压缩：对话到了上限（默认 20 万 token，设置里可调），分身把前情凝成一段摘要，之后只凭摘要和还没回应的话接着做。输入框下方的"灵石"显示眼下的对话占了多少，点开能看会话累计用量、直接改上限
- 外来法器（MCP）：在设置里贴上 MCP 服务的配置（通用的 `mcpServers` 写法，本机程序或远程网址都行），服务提供的工具就交给分身用。这些工具做什么由服务决定，所以无论哪种禁制，每次动用都要先批准，可以选"之后都准"或"这处洞府里永远都准"
- 上网取网页：分身可以用 `fetch_url` 取一个网址的内容来读（文档、issue、原始文件），网页会转成纯文字。请求会发到本机之外，所以每个网站第一次访问都要批准，可以选"之后这个网站都准"。要找网页用下一条的搜索
- 联网搜索：分身可以用 `web_search` 搜网页，拿回标题、网址和摘要，再用 `fetch_url` 读全文。搜索走智谱的搜索接口，用的就是 GLM 的密钥，换哪家模型都能搜；没存 GLM 密钥时不提供这个工具。搜索按次计费（基础版约 0.01 元），每次搜索前要批准，可以选"之后都准"。设置里能换搜索引擎
- 技能：专项的做事说明，平时不占上下文。每门技能是一个文件夹加一份 `SKILL.md`，放在 `~/.odg/skills/` 对所有会话生效，放在项目的 `.odg/skills/` 只对这个项目生效。分身只看得到名字和一句描述，任务对得上时才用 `load_skill` 读全文
- 待办清单：事情分好几步时，分身列出每一步、做完一步勾一步，右侧"计划"一栏随时能看
- 子分身：事情能拆成互不相干的几块时，分身可以用 `delegate` 一次派出最多八个子分身，各办一块、同时进行，办完把回报交回来。每个子分身是一个独立的会话，沿用主分身当时的禁制和已经准过的事，自己要请示的事在它自己的页面上请示；侧栏里列在主分身下面，对话里那张"派出子分身"的卡片能看到各自的状态并点进去。子分身不知道主分身聊过什么，也不能再派子分身。它们共用同一个洞府，靠任务分工避开同一个文件；主分身的撤销不管子分身改的文件，要撤到子分身自己的页面上撤
- 独立工作树：洞府是 Git 仓库时，侧栏洞府名旁多一个分支图标，点它化出的分身有自己的一份工作树（Git worktree，放在 `~/.odg/worktrees/`）和一条 `odg/…` 分支，从洞府当前的提交起步。它改它的，不碰洞府里的文件，所以几个分身可以同时在一个项目上干活。干完点标题栏的"并回"：把它工作树里的改动提交，合并进洞府当前检出的分支；合并有冲突就原样撤回并告诉你是哪些文件，洞府里什么都不变。洞府里还没提交的改动不会带进工作树。删除这样的分身会连工作树一起删，没提交的改动就没了，提交过但没并回的留在那条分支上
- 项目里的规矩：洞府根目录有 `AGENTS.md`（没有就看 `CLAUDE.md`）的话，分身每轮开始时读它，照里面的规矩办事；文件改了，下一轮生效
- 撤销：分身每次改文件前先存下原样，可以撤回某一轮起的全部改动。分身改过之后又被别人动过的文件不会被盖掉。只管改文件工具的改动，命令改的文件撤不了
- 图片：把截图粘贴进输入框，或点"附图"选文件，分身就能看图说话（PNG、JPEG、GIF、WebP，每张不超过 3.7 MB，一次最多 8 张）。功法得认图才行：Claude、OpenAI、`deepseek-flash`、`kimi-k3.1-pro`、`kimi-k3`、`glm-5.3-flash` 认图；`glm-5.3` 和 `deepseek-v4-pro` 只认字，附图按钮会禁用并说明
- 分身干活时可以中途传音，不打断它当前这一步；也可以随时收回
- 分身回话里的代码按语言上色，每段代码都能一键复制；会话标题旁显示洞府里检出的 Git 分支
- 亮暗两套主题

还不能做的事，以及接下来的顺序，见[路线图](doc/ROADMAP.md)。其中最要紧的两条：真实接口只有 GLM 用密钥实测过，其余几家只用模拟的模型服务跑通；还没有安装包。

## 运行

需要 Rust、Node.js 和 pnpm；Windows 上还需要 Visual Studio 的 C++ 构建工具和 WebView2。

```sh
pnpm install
pnpm tauri dev
```

打包成可执行文件：

```sh
pnpm tauri build
```

启动后在**设置**里选模型供应商和模型，填上那一家的 API 密钥；也可以在启动前导出对应的环境变量（见下文）。

## 界面里的说法

界面文案带一点修仙的味道。涉及授权、密钥和报错的地方，修仙说法旁边都保留了字面意思。

| 界面上写的 | 意思 |
|---|---|
| 本尊 | 你 |
| 分身 | agent |
| 洞府 | 会话所在的文件夹 |
| 开辟洞府 | 选一个文件夹，在里面新建会话；侧栏里洞府名字旁的"+"是在这处洞府里再建一个 |
| 化出分身 | 新建会话 |
| 传令 / 传音 | 发送指令 / 分身干活时中途插话 |
| 收回分身 | 停止当前这一轮 |
| 候旨、请本尊定夺 | 等你批准 |
| 准 / 驳回 | 批准 / 拒绝 |
| 功法 | 模型 |
| 境界：练气、筑基、金丹、元婴、化神 | 分身每一步想多深，从浅到深五档 |
| 灵石 | 接口额度 |
| 禁制：步步请示、自行改文件、先谋后动、放手施为 | 权限模式 |

## 界面风格

风格叫"符箓"，材质只表达一件事：谁做了什么。

- 白纸是本尊的法旨，下面垫着一角黄符，表示分身已经接令。
- 黄符是分身的手笔，每张符开头盖一枚朱砂印，一个字说明是哪类动作：读、搜、改、建、行。
- 朱丝栏的奏折是候本尊定夺的事，朱砂只在这里和印上出现。
- 青玉色是传令，朱砂色是批准，两种动作不共用一种颜色。

文字统一用[霞鹜文楷 轻便版](https://github.com/lxgw/LxgwWenKai-Lite)（LXGW WenKai Lite，SIL OFL 1.1 许可），标题和印用它的粗体；代码用 Atkinson Hyperlegible Mono。两款字体都随应用打包，不依赖系统字体。

## 结构

```
crates/odg-core/   核心库，不依赖桌面外壳
  events.rs        会话事件定义
  session.rs       追加式会话日志，以及从日志推导模型请求
  providers.rs     模型供应商列表，按会话的供应商把请求分给对应客户端
  anthropic.rs     Anthropic Messages API 流式客户端
  openai_responses.rs  OpenAI Responses API 流式客户端
  openai_chat.rs   Chat Completions 流式客户端：DeepSeek、Kimi、GLM 和其他兼容服务
  llm.rs           客户端共用的请求、重试和报错处理
  tools.rs         工具：read_file、search、find_files、edit_file、write_file、run_command、command_output、stop_command
  jobs.rs          后台命令：启动、读输出、停止
  mcp.rs           MCP 客户端：读服务清单、连接、列工具、调工具
  skills.rs        技能：找 SKILL.md，按名读取
  web.rs           取网页，把 HTML 化成纯文字
  worktree.rs      独立工作树：建、并回、删
  policy.rs        四种禁制下，哪些操作要先批准
  safety.rs        放手施为的命令安全检查
  agent.rs         agent 循环：回合、步骤、审批、传音、收回、压缩
  undo.rs          改文件前的快照，按轮撤回
  settings.rs      设置和密钥
crates/odg-cli/    命令行版 odg：不开窗口跑一次任务
src-tauri/         Tauri 命令和事件转发
src/               React 界面
doc/               路线图和截图
app-icon.svg       应用图标的源文件
```

## 几条设计约定

- **日志是唯一事实来源。** 每个会话是一个只追加的文件 `~/.odg/sessions/<id>/session.v1.jsonl`。发给模型的每个请求都只从日志推导，界面也只从日志折叠出来，所以重开会话看到的和之前完全一样。
- **压缩也是一条事件。** 对话太长时，摘要作为 `context/compacted` 事件追加进日志，之后的请求从它开始推导；它之前的内容留在日志里，界面照常显示，只是不再发给模型。压缩只发生在两步之间，不会卡在工具调用中间。
- **历史只追加，不改写。** 模型返回的内容块（包括思考块）原样保存、原样回放。DeepSeek、Kimi、GLM 的 `reasoning_content` 和 OpenAI 的加密推理项也一样，后续请求原样带回。
- **会话不换供应商，但可以换模型。** 会话头记下化出时的供应商，所以日志里只会有一家的内容块，不需要在各家格式之间转换。同一家之内换模型是一条 `model/changed` 事件，之后的请求发给新模型；历史原样带过去，不删思考内容，新模型读不了的部分由供应商自己略过。只能在两轮之间换。
- **每个工具调用都有结果。** 无论一轮是正常结束、被收回、出错还是应用崩溃，日志里不会留下没有结果的工具调用。
- **模型可见的新输入都对应一种会话事件。** 加工具时同时定好审批规则、界面卡片和测试。

## 环境变量

| 变量 | 作用 |
|---|---|
| `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`MOONSHOT_API_KEY`、`ZHIPUAI_API_KEY` | 对应供应商没有在设置里保存密钥时使用 |
| `ANTHROPIC_BASE_URL` | 把 Anthropic 请求发到自己的网关；此时不发送只有官方接口支持的字段。其他供应商的地址在设置里改 |
| `ODG_E2E_WORKSPACE` | 端到端测试用：化出分身时直接用这个文件夹，不弹系统的选文件夹对话框 |
| `ODG_HOME` | 会话和设置的存放目录，默认 `~/.odg`。设了它，密钥就存在这个目录自己的 `credentials.json` 里，不碰系统凭据管理器 |

设置里保存的密钥存进系统的凭据管理器：Windows 凭据管理器、macOS 钥匙串、Linux 的 Secret Service，条目归在 `OmniDoppelganger` 名下。早先存在 `~/.odg/credentials.json` 里的密钥，启动时会自动搬过去并从文件里删掉。凭据管理器用不了时（比如 Linux 上没有运行 Secret Service），密钥才留在这个明文文件里，设置页会注明。

## 命令行

不开窗口也能跑一次任务：

```sh
cargo run -p odg-cli -- "给 README 补一节安装说明"      # 开发时
odg -C ../other-project --mode auto "跑一遍测试，修掉失败的"  # 装好之后
```

它和桌面应用用的是同一个分身、同一个家目录：设置、密钥、长期许可、MCP 服务、技能都通用，跑出来的会话之后在桌面应用里也看得到。分身说的话走标准输出，它做的事和要请示的事走标准错误，所以可以直接把结果接进管道。要请示时，在终端里会问你；没有终端（比如在脚本里）默认一律驳回，加 `--yes` 一律批准。`odg --help` 列出全部选项。

## 测试

```sh
cargo test -p odg-core -p odg-cli
pnpm test
```

核心库的测试不需要 API 密钥：模型由脚本化的替身扮演，工具在临时目录里真实执行。界面的测试覆盖从会话日志折叠出界面的那部分（`src/lib/fold.ts`）。

端到端测试驱动真实的应用窗口，模型由一个按脚本回放的本地服务扮演（只支持 Windows，靠 WebView2 的调试端口）：

```sh
pnpm e2e --build   # 先把应用构建到 target/e2e，再跑
pnpm e2e           # 用上次的构建直接跑
```

它走一遍完整的一轮：化出分身、传令、分身建文件、命令等审批、批准、收尾，再撤回改动，然后核对界面、磁盘上的文件、发给模型的请求和会话日志。应用跑在临时目录里的家目录、工作文件夹和浏览器数据上，不碰你的会话和密钥，也不影响已经开着的应用。脚本在 `e2e/`：`mock-llm.mjs` 是模拟的模型服务，`cdp.mjs` 是调试端口的客户端，`run.mjs` 是测试本身。

每次推送到 `main` 和每个合并请求都会自动跑一遍（`.github/workflows/ci.yml`）：核心库和命令行在 Windows、Linux、macOS 上各跑静态检查和测试，前端和桌面外壳在 Windows 上跑测试、构建和静态检查。只改文档不触发。

## Logo 和图标

logo 是一个沿 S 线分成两半的圆，盖在一方朱砂印上：白的一半是本尊，金的一半是分身，两半微微拉开，合则为一，分则为二。界面里不带印底的那个小标记是同一个图形，用来表示状态：空闲时两半合拢，运功时分身那半来回游离，候旨时它变成朱砂色并停在外面。

应用图标的源文件是 `app-icon.svg`。改了它之后重新生成各个尺寸：

```sh
pnpm tauri icon app-icon.svg
```

这条命令还会生成 `src-tauri/icons/android` 和 `ios` 两个目录，桌面应用用不到，可以删掉。构建脚本只在 `src-tauri/tauri.conf.json` 变化时才重新嵌入图标，所以生成后要改动或 `touch` 一下这个文件再构建。
