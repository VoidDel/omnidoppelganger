# 路线图

OmniDoppelganger 从 v0.1 到 v1.0 分五个阶段，阶段名借用五层境界。每个阶段有一句目标、一组事项和一条完成标准；达到完成标准才进入下一阶段。

工作量按一个人全职开发粗估：小是几天，中是一两周，大是数周。这里不排日期。

## 现状（v0.1）

已有：单会话 agent 循环、四个工具（读文件、搜索、改文件、跑命令）、审批、追加式会话日志、Anthropic 流式客户端、符箓界面、核心库单元测试。

主要缺口：

- 真实接口没有实测过，只用模拟的模型服务跑通过
- 没有安装包

## 排序的理由

- **压缩和撤销排最前。** 没有压缩，长任务必然中途失败；没有撤销，使用者不敢放手让分身改文件。
- **多模型和 MCP 放第三阶段。** 它们扩大能力，但不解决"能不能天天用"。
- **沙箱排后。** Windows 上实现成本很高，而现有的逐条审批已经是一道基本防线。

## 暂时不做

- 运行时热插拔的插件体系：复杂度高，MCP 和技能已经能覆盖大部分扩展需求。
- 网页版和远程访问。
- 操作电脑和浏览器。
- 遥测上报。

## 贯穿始终的三条规矩

- 模型能看到的每一种新输入，都对应一种会话事件。
- 每加一个工具，同时定好审批规则、界面卡片和测试。
- 会话格式一改动就升版本号。
