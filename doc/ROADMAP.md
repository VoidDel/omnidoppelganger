# 路线图

OmniDoppelganger 从 v0.1 到 v1.0 分五个阶段，阶段名借用五层境界。每个阶段有一句目标、一组事项和一条完成标准；达到完成标准才进入下一阶段。

工作量按一个人全职开发粗估：小是几天，中是一两周，大是数周。这里不排日期。

## 现状（v0.7.0）

已有：agent 循环（回合、步骤、审批、传音与立即传音、收回、压缩）、内置 27 种工具（另有 MCP 服务带来的）、五种禁制、通行符（长期许可）、追加式会话日志与回溯分叉、五家 HTTP 供应商与两类兼容服务、五家本机编码 CLI 无头流式引擎（Antigravity `agy`、Codex、Claude Code、Cursor、Grok，支持宗门启用开关）、MCP 法器（工具与资源）、秘籍、代码导航（Rust、TypeScript、Python 的语言服务可由应用下载）、子分身、独立工作树、功课（定时任务）、命令沙箱（Linux 和 macOS）、文档运行时、画图与丹青、代码工作台（侧边文件管理、多标签代码高亮查看器、Git 管理与 Diff 对照、旁聊只读会话、侧边交互式本地 PTY 终端）、命令行版 `odg`，以及核心库的单元测试和一套 Windows 上的端到端测试。

主要缺口：

- 真实接口只有 GLM 用密钥实测过，Anthropic、OpenAI、DeepSeek、Kimi 只用模拟的模型服务跑通过
- 没有签名和公证的安装包，也没有自动更新；安装包本身能由 `pnpm tauri build` 打出来
- 端到端测试还没接进持续集成
- Windows 上的命令沙箱还没有（卡在哪里见 [WINDOWS_SANDBOX.md](WINDOWS_SANDBOX.md)）

## 排序的理由

- **压缩和撤销排最前。** 没有压缩，长任务必然中途失败；没有撤销，使用者不敢放手让分身改文件。
- **多模型和 MCP 放第三阶段。** 它们扩大能力，但不解决"能不能天天用"。
- **沙箱排后。** Windows 上实现成本很高，而现有的逐条审批已经是一道基本防线。

## 暂时不做

- 运行时热插拔的插件体系：复杂度高，MCP 和秘籍已经能覆盖大部分扩展需求。
- 网页版和远程访问。
- 操作电脑和浏览器。
- 遥测上报。

## 贯穿始终的三条规矩

- 模型能看到的每一种新输入，都对应一种会话事件。
- 每加一个工具，同时定好审批规则、界面卡片和测试。
- 会话格式一改动就升版本号。
