# 路线图

OmniDoppelganger 从 v0.1 到 v1.0 分五个阶段，阶段名借用五层境界。每个阶段有一句目标、一组事项和一条完成标准；达到完成标准才进入下一阶段。

工作量按一个人全职开发粗估：小是几天，中是一两周，大是数周。这里不排日期。

## 现状（v1.0.0）

已全面定版落地：agent 循环（回合、步骤、审批、传音与立即传音、收回、带尾保留压缩、异常中断状态自愈守卫）、内置 28 种工具（含 `batch_inspect` 批量探查，另有 MCP 服务带来的）、五种禁制、护法模型审核、项目信任门禁与通行符（长期许可）、追加式会话日志（`session.v1.jsonl`）与逐步回溯分叉、七家云端 HTTP 供应商（Anthropic、OpenAI、Google Gemini、OpenRouter、DeepSeek、Kimi、GLM）与本机免密服务（Ollama、Magpie）及两类兼容服务、六家本机编码 CLI 无头流式引擎（Antigravity `agy`、Codex、Claude Code、Cursor、Grok、OpenCode，支持宗门启用开关与五档权限映射）、MCP 法器（工具与资源）、十五部内置秘籍与参数化提示词模板、代码导航（Rust、TypeScript、Python 的独立语言服务可由应用按校验码下载）、子分身（含 `read_only: true` 只读探查型子分身）、独立工作树（桌面与 `odg --land` 一键并回）、功课（定时任务）与后台系统桌面通知、命令沙箱（Linux Landlock 与 macOS `sandbox-exec`，含 `.git/{hooks,config}` 写保护）及 Unix `~/.odg` `0700`/`0600` 私有权限保护、文房文档运行时、画图与丹青、代码工作台（侧边文件树、多标签虚拟滚动代码查看器、Git 管理与分块 Diff 对照、旁聊只读会话、侧边交互式本地 PTY 终端）、流式渲染与长会话性能优化（后端 12ms 流合并、前端 `rAF` 批处理与增量 `fold()`）、三套界面语言切换（雅言中文 / 现代中文 / English）与键盘无障碍支持、三平台商业签名公证安装包与 `tauri-plugin-updater` 应用内自动更新、三平台独立分发的命令行 `odg`（支持 `--version`、续聊、`-w --mode bypass`、`--land`、NDJSON 流与 Markdown 导出），以及覆盖 Windows、macOS、Linux 三端的 CI 静态检查、单测、回归评测集、版本/文档一致性门禁与 Windows 真实窗口端到端测试。

后续持续演进方向：

- Windows 原生免管理员命令写入结界（受限令牌对 Node 子进程管道的兼容性限制与备选方案见 [WINDOWS_SANDBOX.md](WINDOWS_SANDBOX.md)）
- 子分身脱离主回合后台异步运行、独立续聊与子分身级工作树隔离

## 排序的理由

- **压缩和撤销排最前。** 没有压缩，长任务必然中途失败；没有撤销，使用者不敢放手让分身改文件。
- **多模型和 MCP 放第三阶段。** 它们扩大能力，但不解决"能不能天天用"。
- **沙箱排后。** Windows 上实现成本很高，而现有的逐条审批已经是一道基本防线。

## 暂时不做

- 运行时热插拔的插件体系：复杂度高，MCP 和秘籍已经能覆盖大部分扩展需求。
- 网页版和远程访问。
- 遥测上报。

## 贯穿始终的三条规矩

- 模型能看到的每一种新输入，都对应一种会话事件。
- 每加一个工具，同时定好审批规则、界面卡片和测试。
- 会话格式一改动就升版本号。
