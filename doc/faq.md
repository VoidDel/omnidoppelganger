# 常见问题

操作步骤见 [使用手册](user-guide.md)。下面都没有覆盖到时，可以在 [Issues](https://github.com/VoidDel/omnidoppelganger/issues/new/choose) 反馈。

## 安装与启动

### Windows 安装或启动时提示“Windows 已保护你的电脑”

安装包目前尚未购买商业代码签名证书，SmartScreen 对未签名的新程序都会给出这个提示。确认安装包下载自官方仓库的 [Releases](https://github.com/VoidDel/omnidoppelganger/releases) 后，点 **更多信息 › 仍要运行** 即可。

### macOS 打开时提示“已损坏，无法打开”或“无法验证开发者”

macOS 安装包目前采用本地 Ad-hoc 签名，尚未经过 Apple 公证（Notarization），Gatekeeper 会给浏览器下载的 `.dmg` 打上隔离标记。把应用拖进“应用程序”后，打开终端执行一次下面这条命令即可正常启动：

```bash
xattr -cr /Applications/OmniDoppelganger.app
```

### 有 Intel 芯片的 macOS 安装包吗？

预构建的 `.dmg` 目前面向 Apple Silicon（M 系列芯片）。Intel Mac 可以安装 Rust 1.85+、Node.js 24 与 pnpm 后克隆仓库，在本机执行 `pnpm install && pnpm tauri build` 自行打包运行。

### 卸载后怎么把历史会话和保存的密钥彻底删干净？

卸载程序默认保留用户数据，避免误删对话与作品。想彻底清空时：

1. 删除主目录下的 `~/.odg` 文件夹（Windows 在 `%USERPROFILE%\.odg`）。
2. 在系统凭据管理器（Windows 凭据管理器、macOS“钥匙串访问”、Linux Secret Service）里搜索 `OmniDoppelganger` 并删除对应密钥条目。

## 宗门、心法与本机 CLI

### 电脑上已经装了 `claude`、`codex`、`agy` 或 `opencode`，为什么设置里显示“未装 CLI”？

桌面应用从启动台、访达或开始菜单启动时，系统给它的环境变量 `PATH` 往往比你在交互式终端里看到的短。程序启动时会自动补齐 Homebrew、nvm、fnm、Volta、`~/.local/bin`、`~/.cargo/bin`、npm 全局目录等常见路径；如果你的 CLI 装在自定义目录，有两种办法：

1. 直接从能运行该命令的终端里启动桌面应用，应用会原样继承终端的 `PATH`。
2. 设置对应的环境变量指明可执行文件绝对路径：`ODG_AGY_BIN`、`ODG_CODEX_BIN`、`ODG_CLAUDE_BIN`、`ODG_CURSOR_AGENT_BIN`、`ODG_GROK_BIN` 或 `ODG_OPENCODE_BIN`。

### 填了 API 密钥，但点刷新心法列表提示拉取失败？

部分兼容中转站或企业网关没有开放 `/v1/models` 列表查询接口，或者返回格式与官方不同。这不影响正常对话——直接在“心法”输入框里手动输入服务商提供的模型 ID（例如 `claude-sonnet-4-6` 或 `deepseek-v3`）回车保存即可。

### 为什么有些模型粘贴截图时提示附不了图片？

只有具备视觉能力的模型才能看图。比如智谱的 `glm-5.3-flash`、DeepSeek 的 `deepseek-flash`、Claude、OpenAI、Gemini 等支持图片输入，而纯文本推理模型（如 `glm-5.3`、`deepseek-v4-pro`）只接收文字。需要发截图排错时，在输入框下方把当前分身临时切到支持看图的心法即可，聊完还能随时切回来。

### 把心法选成 `auto` 是怎么选模型的？

`auto` 是内置的按思考深度分流路由：当输入框下方的“境界”处于 **练气** 或 **筑基** 时，自动把请求发给当前宗门下的高速轻量模型（响应快、单价低，适合简单问答和小改）；当境界调到 **金丹**、**元婴** 或 **化神** 时，自动切到该宗门的主力旗舰模型处理复杂设计与疑难排错。

### 怎么连接本机跑的 Ollama、LM Studio 或 vLLM？

- **Ollama**：在“设置 › 心法”直接选内置的 **Ollama（本机模型）**，保持默认地址 `http://127.0.0.1:11434/v1`，无需填密钥，选好你已 `ollama pull` 下来的模型即可。注意选用支持 Tool Calling（工具调用）的模型，否则分身无法读写文件。
- **LM Studio / vLLM / llama.cpp**：点 **新增宗门 › OpenAI 兼容服务**，填入本机服务地址（如 `http://127.0.0.1:1234/v1`），随便填一个占位密钥（如 `local`）并输入模型名即可。

### 灵石面板里显示的美元（`$`）花费准吗？

这只是按各模型公开 API 标价（输入、输出、缓存读取各自单价）在本地估算的参考值，实际扣费以各模型供应商后台账单为准。使用包月订阅类本机 CLI（如 `agy`、`claude`、`codex`）或本机 Ollama 模型时不会向 API 按量计费。

## 洞府安全、禁制与审批

### 为什么刚打开一个克隆下来的项目，顶部提示检测到项目配置暂未加载？

这是 **项目信任（Project Trust）** 保护机制。仓库根目录下的 `AGENTS.md` / `CLAUDE.md`、`.odg/skills/` 和 `.odg/prompts/` 会直接进入分身的系统提示词或命令列表；如果打开一个来历不明的仓库就无条件加载，里面的隐藏指令可能会诱导分身执行危险操作。确认仓库来源可靠后，点横幅上的 **信任此洞府**（或输入 `/trust`）即可永久放行该目录；日后想反悔可在“设置 › 禁制 › 通行符”里收回。

### 为什么输入框下方的禁制菜单里选不了“全权托付”？

“全权托付”会跳过一切审批（包括任意命令、洞府外路径、`.git` 修改与联网），风险极高，因此程序故意做了三道限制：

1. **只能在“独立工作树”分身上开启**（点侧栏洞府名旁的分支图标化出的分身），不能在直接操作原仓库的普通分身上开启。
2. 不能设为新分身的默认禁制，也不能用于定时“功课”。
3. 按 `Shift+Tab` 快捷键轮换禁制时永远不会切进“全权托付”，必须手动从菜单点选并在确认弹窗中点头。

### 为什么有些命令审批时没有“此府永准”或“之后都准”选项？

只有结构单纯、前缀固定的单条命令（如 `cargo test`、`pnpm build`）才允许按前缀长期放行。凡是包含管道 `|`、分号 `;`、`&&`、重定向 `>`、命令替换 `$()`、环境变量展开，或者直接调用 `sh`、`bash`、`pwsh`、`python`、`node` 等通用解释器执行脚本代码的命令，如果按前缀放行就等于放行了任意代码，因此每次都必须单独过目批准。修改 `.git/` 下的文件同理（防止写入恶意 Git Hook）。

### 使用本机 CLI（`claude`、`codex`、`cursor-agent`、`grok`、`opencode`、`agy`）时，禁制和审批怎么生效？

本机 CLI 以无头流式模式（`--print` / `exec` / `run`）运行，无法中途挂起弹出应用内的朱丝栏审批卡片，因此五种禁制直接映射为对应 CLI 的权限与沙箱参数：

- **步步请示 / 先谋后动**：以只读/规划档位运行，不自动修改文件、不执行命令。
- **府内自便**（默认）：允许修改洞府内文件，但不自动放行外部命令（Codex 使用 `workspace-write` 沙箱）；若需要让 CLI 自行跑测试或构建命令，请切换到 **放手施为**。
- **放手施为**：启用对应 CLI 的自动/分类器模式，并桥接已启用的 MCP 法器。
- **全权托付**：仅在独立工作树下可用，跳过对应 CLI 的全部权限询问（若开启了“结界”，支持沙箱参数的 CLI 仍会附带沙箱限制）。

### “撤回这一轮”能把分身跑命令改坏的文件也撤回来吗？

不能。撤回快照只记录分身通过文件工具（包括内置引擎及外部 CLI 的 `edit_file`、`write_file`、`delete_file`、`move_file`）对洞府内文件所做的修改、新建、删除或移动。分身通过 `run_command` 运行脚本、`git checkout`、代码生成器或格式化工具改写的文件，需要借助左侧 **Git** 面板或你自己的 Git 提交记录来还原。

### 开启“结界”（命令沙箱）后，运行 `pnpm install` 或 `cargo test` 报权限错误写不进缓存怎么办？

结界默认只允许命令往**当前洞府**和**系统临时目录**写文件，而包管理器（如 `~/.npm`、`~/.local/share/pnpm`、`~/.cargo`）常需要写用户主目录下的全局缓存。你有两种处理方式：

1. **临时放行单次**：分身识别到是被结界拦住后，会主动发出一张“请求出结界重跑一次”的审批卡，点批准即可单次在结界外执行。
2. **加入结界白名单**：在 **设置 › 禁制 › 结界** 的“额外可写目录”里把常用的包缓存目录添进去，既保住其他目录不被误改，又不耽误日常安装编译。

## 文件、文档、法器与代码导航

### 为什么有的 PDF 或旧版 `.doc`、`.ppt` 附不进对话？

- **扫描版 PDF**：纯图片扫描成的 PDF 里没有可提取的文字层。你可以把关键几页截图粘贴进输入框，交给支持看图的心法直接识图阅读。
- **旧版二进制 `.doc` / `.ppt`**：内置文档解析器只读取现代开放 XML 格式（`.docx`、`.pptx`），用 Office、WPS 或 LibreOffice 另存为 `.docx` / `.pptx` 后即可正常附带（旧版 `.xls` 表格已直接支持，无需转换）。

### “文房”（Python 运行时）下载很慢或中途报错怎么办？

文房首次准备需从 GitHub 与 PyPI 下载约 90 MB 的独立 Python 3.12 与科学计算/文档库，并逐个校验 SHA-256 哈希。国内网络较慢时，可以在启动应用前设置镜像环境变量再点安装（校验码核验照旧生效，保证安全）：

- `ODG_PYTHON_MIRROR`：替换 `python-build-standalone` 的下载前缀地址。
- `PIP_INDEX_URL`：替换 pip 包源（例如 `https://pypi.tuna.tsinghua.edu.cn/simple`）。

### 启用本机 MCP 法器（如 Playwright、Fetch）时报找不到 `npx` 或 `uvx`？

Playwright、Chrome DevTools、Memory、Sequential Thinking 依赖本机安装 [Node.js](https://nodejs.org/)（提供 `npx`），Fetch 依赖安装 [uv](https://docs.astral.sh/uv/)（提供 `uvx`）。装好后在“法器”页重新拨动开关即可连接；无需 Node / uv 的纯云端搜索可启用内置的 **Exa** 或 **Context7**。

### 代码导航（`code_nav`）第一次调用为什么比较慢？

首次在某个仓库里查询某门语言时，对应的语言服务器（如 `rust-analyzer`）会在后台启动并建立全仓符号索引，大型 Rust 或 TypeScript 仓库可能需要十几秒到一分钟；索引建好后，同一洞府下的所有分身都会复用这同一个后台实例，后续查询就是毫秒级响应。

## 分叉、工作树与问题反馈

### “从这里分叉”会把项目文件夹也复制一份吗？

不会。**分叉**只复制那一步之前的聊天上下文，原分身和新分身仍然面对同一个洞府文件夹。如果你想让两个分身同时改代码且互不覆盖，应该点侧栏洞府名旁的 **分支图标** 创建 **独立工作树（Worktree）** 分身。

### 独立工作树点“并回”时如果和主分支有冲突，会把我的工作区搞乱吗？

不会。“并回”在合并检测到冲突时会立即完整回滚合并状态，原洞府检出的分支和文件保持分毫不差，并明确列出是哪几个文件产生了冲突，留给你从容处理。

### 在哪里看版本更新？检查更新失败是怎么回事？

打开 **设置 › 外观 › 版本与更新** 点 **检查更新**，应用会请求 GitHub Releases 接口比对最新正式版。如果本机网络无法直连 `api.github.com`，检查会提示网络错误，直接浏览器访问 [Releases 页面](https://github.com/VoidDel/omnidoppelganger/releases) 查看即可。

### 反馈 Bug 时怎么附上排查信息又不泄露隐私？

在 [提交问题反馈](https://github.com/VoidDel/omnidoppelganger/issues/new?template=bug_report.yml) 时，请写明版本号、操作系统、所用的宗门/CLI 类型及复现步骤。如需附上某次异常会话的记录，优先用会话的 **导出 Markdown**（`/export`）导出文本并删去其中的私有代码片段、路径与业务敏感词；**切勿直接上传 `~/.odg/mcp.json` 或 `credentials.json`**，因为里面可能含有你的明文令牌。
