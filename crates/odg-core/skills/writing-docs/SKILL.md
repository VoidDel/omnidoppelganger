# 写文档

文档的好坏只看一件事：读的人读完，能不能做成他想做的事。

## 先想清楚

- **写给谁**：第一次来的使用者、要接着开发的人、调用接口的人，要的东西完全不同。一份文档最好只对一类人。
- **他读完要能做什么**：装上并跑起来、用某个功能、改某段代码、排查某个问题。没有这个目标的段落可以删掉。
- 先读代码和已有文档，确认写的每句话都是真的：命令真能跑，参数名真是这个，默认值真是这个。不确定的去试一下。

## 怎么写

- 先给最常用的路径：怎么装、怎么跑、最简单的一个例子。例外情况和高级用法放在后面。
- 用具体的东西：真实的命令、能复制的例子、实际的输出。"配置相关参数"不如直接给出那几行配置。
- 一段只说一件事，句子短，用使用者的说法而不是代码里的名字。术语第一次出现时解释一下。
- 照项目已有文档的语言、格式和语气写。
- 代码注释写**为什么**，不写代码本身已经说清楚的**做什么**。

## 不要写

- 读代码一眼就能看出来的东西，以及很快会过时的细节（比如完整的文件清单）。
- 还没实现的功能，当成已经有了来写。
- 空泛的形容（"强大的"、"灵活的"）和营销腔。

## 完成之后

照着文档自己走一遍：命令跑一跑，链接点一点，例子试一试。走不通的地方改掉。
