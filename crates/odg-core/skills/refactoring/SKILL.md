# 安全重构

重构的定义是**改结构、不改行为**。一旦行为变了，就是另一件事，要单独做、单独说。

## 动手之前

- 弄清要达到什么：好读、好改、去掉重复、给新功能腾地方。目标不清楚的重构容易越扩越大。
- 找到兜底：这部分代码有没有测试？没有的，先补几个刻画现有行为的测试（哪怕行为看起来不对，也先按现状写下来），再动结构。
- 找全使用的地方：用 `search` 搜函数名、类型名、字符串里的引用、配置文件、文档；动态调用和反射要特别留意。

## 怎么做

- **小步走**：一次只做一种变换（改名、提取函数、移动文件、合并重复）。每一步之后都编译、跑测试，确认还是好的再走下一步。
- 机械的改动（改名、移动）和有判断的改动（改接口、改逻辑）分开做。
- 公开的接口要改时，考虑先加新的、保留旧的转发过去，等调用方都换了再删。
- 路上发现了 bug，记下来告诉用户，不要在重构里顺手修掉：那会让"行为不变"无从验证。
- 范围控制在要求之内。看到别处也想整理，先问。

## 完成之后

- 跑完整的测试、类型检查和格式检查。
- 汇报：做了哪几步变换、改了哪些文件、怎么确认行为没变；有没有发现但没动的问题。
